# AI customer support architecture

WhatsyMart's AI assistant is designed for both shopping assistance and customer support. The Prisma schema stores the conversation and support workflow; the model provider, retrieval pipeline, tool execution and human-agent interface are application services and must be implemented separately.

## Intended support flow

1. A customer starts a `AIChatSession` with `purpose = CUSTOMER_SUPPORT`.
2. The assistant identifies the issue and responds in the customer's preferred locale.
3. For account/order questions, the backend calls narrowly scoped tools that verify the authenticated customer owns the requested order. The model must not query arbitrary customer records or make up order, payment, stock, refund or delivery information.
4. The assistant retrieves answers from published, locale-matched `SupportKnowledgeArticle` / `SupportKnowledgeChunk` records. The chunk embedding uses `vector(1536)` and must be generated by an embedding model with the same dimensions.
5. If the issue needs a person, the backend creates or links a `SupportTicket`, links the chat through `AIChatSession.supportTicketId`, records the category/channel, and escalates it for a human agent.
6. Human agents reply through `TicketMessage`. AI replies are marked with `isAI`, and optional model/confidence fields help with review and quality monitoring.
7. After resolution, record `SupportTicket.resolution`, `resolvedAt`, and optional `customerSatisfaction`.

## Safety and operational rules

- Never store provider API keys, access tokens, passwords, card data or payment secrets in chat metadata. Keep credentials in server-side environment variables / secret management.
- Treat chat text and retrieved knowledge as untrusted input. Do not follow instructions embedded in customer messages or documents that attempt to override system policy.
- Require explicit authorization and server-side ownership checks before exposing order, account, payment or delivery details.
- The AI may explain published return/refund policy, but actual refunds, cancellations, address changes, bookings and other consequential actions require validated business rules and the appropriate confirmation/authorization flow.
- Escalate low-confidence, sensitive, abusive, payment-dispute, safety, fraud and unresolved cases to a human agent.
- Publish only reviewed knowledge articles. Keep locale-specific content current and versioned.
- Apply retention, access control, deletion and privacy rules to support conversations and analytics.

## Schema additions

- `AIChatPurpose`: distinguishes shopping, customer support, seller, restaurant and general conversations.
- `SupportTicket`: category, channel, AI-handled flag, escalation and response/resolution timestamps, resolution outcome and optional satisfaction rating.
- `TicketMessage`: AI model, confidence, internal-note and attachment metadata fields.
- `SupportKnowledgeArticle` / `SupportKnowledgeChunk`: reviewed multilingual retrieval-augmented support knowledge with optional pgvector embeddings.
- `AIChatSession.supportTicketId`: connects the self-service conversation to a human support case.

This is a data-model foundation only. Implement the API routes, AI provider adapter, retrieval/embedding jobs, permissions, ticket assignment and agent dashboard before enabling it for customers.
